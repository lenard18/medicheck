Módulos del sistema

¿Qué hace MediCheck IA?

Cada módulo resuelve una necesidad específica del ecosistema de salud digital.

🧬
Análisis de síntomas con IA
El paciente describe sus síntomas en texto libre y el sistema los analiza con Ollama (llama3.2:3b) para clasificarlos en LEVE, MODERADO o GRAVE con recomendación personalizada.
Ollama + llama3.2
📋
Registro y perfil de paciente
Formulario guiado de 4 pasos: datos personales, información médica (alergias, medicamentos, grupo sanguíneo), contacto de emergencia y preferencias de atención.
Vue 3 multi-paso
👨‍⚕️
Registro y perfil médico
Proceso de 3 pasos: datos personales, datos profesionales (licencia, RETHUS, universidad) y carga de documentos obligatorios para verificación.
Multipart upload
✅
Verificación documental
El administrador puede ver, revisar y aprobar cada documento subido por el médico. Los documentos se sirven de forma segura con autenticación JWT via axios blob.
Spring Security
🗺️
Asignación geográfica
El admin visualiza pacientes y médicos en un mapa interactivo. Al seleccionar un paciente, ve los médicos ordenados por proximidad usando la fórmula de Haversine.
Leaflet + Haversine
📧
Alertas automáticas
Si un paciente registra una consulta con nivel GRAVE o MODERADO y tiene médico asignado, el sistema envía automáticamente un email de alerta al médico.
Gmail SMTP
🪪
Vista perfil CV
Cada usuario puede ver su perfil en formato hoja de vida. El administrador puede ver el CV de cualquier usuario desde la tabla de usuarios paginada.
Solo lectura
👥
Gestión de usuarios
Vista paginada (20/página) con filtros por nombre, rol, ciudad y estado de validación. Mantiene posición en la paginación al volver desde el perfil.
JPA Specification
🔐
Seguridad por roles
Autenticación JWT con expiración de 24h. Tres roles independientes (PACIENTE, MÉDICO, ADMIN) con endpoints completamente separados. Perfil incompleto bloquea el acceso.
JWT + RBAC

Arquitectura por capas

🌐 Capa de Presentación :5173
▶

SPA construida con Vue 3 + Vite. No hay rendering server-side. La app se comunica exclusivamente via REST con el backend. El enrutamiento y la autenticación se gestionan completamente en el cliente.

Vue 3 Composition API Vue Router 4 (guardas) Axios (interceptores JWT) Leaflet / OpenStreetMap 14 vistas / 2 componentes localStorage (mc_token, mc_rol, mc_perfil_ok)

▶

API REST con Spring Boot 3. Cada request pasa por el JwtFilter que extrae el email del token y carga el UserDetails. Los controllers delegan la lógica a los services. La capa de repositorio usa JPA + Specification para filtros dinámicos.

Spring Boot 3.5 + Java 17 Spring Security 6 + JWT 9 Controllers REST 5 Services de negocio 6 Repositories JPA JPA Specification (filtros) Lombok @RequiredArgsConstructor GlobalExceptionHandler
↕ JDBC / Hibernate ORM + SQL

▶

PostgreSQL 15. Hibernate gestiona el esquema con ddl-auto=update. El DataSeeder corrige roles y constraints con JdbcTemplate en cada arranque.

Experiencia de usuario

Flujos por tipo de usuario

Haz clic en cada paso para ver los detalles técnicos del flujo.

Registro de cuenta
El paciente crea su cuenta con nombre, email, contraseña y selecciona rol PACIENTE.
POST /api/auth/registro → Retorna JWT + perfilCompleto: false.
El frontend guarda mc_perfil_ok = "false" y redirige a /perfil-paciente.
Completar perfil (4 pasos)
Datos personales → Info médica → Contacto emergencia → Preferencias. Hasta no completar todos los pasos, no se puede acceder al dashboard.
Cada paso tiene validación individual. El botón "Finalizar" valida los 4 pasos completos antes de guardar.
Al terminar: POST /api/paciente/perfil → mc_perfil_ok = "true".
Dashboard y nueva consulta
Accede al dashboard con estadísticas de sus consultas. Crea una nueva consulta describiendo sus síntomas.
POST /api/consultas → El backend analiza con Ollama → Respuesta con nivel LEVE MODERADO o GRAVE + recomendación.
Historial y mapa GPS
Consulta su historial completo. Comparte su ubicación GPS para que el médico pueda verla en el mapa.
GET /api/consultas/mis-consultas para el historial.
POST /api/ubicacion para compartir coordenadas.
GET /api/ubicacion/mi-medico para ver dónde está su médico asignado.
Registro como médico
Crea cuenta seleccionando rol MÉDICO. Recibe JWT con perfilCompleto: false.
Redirigido automáticamente a /registro-medico. El router bloquea cualquier otra ruta hasta completar el perfil.
Completar perfil (3 pasos)
Datos personales → Datos profesionales (licencia, especialidad, universidad) → Subida de documentos obligatorios.
Los documentos obligatorios son: Fotografía profesional, Doc. identidad (frontal/reverso), Diploma universitario, Tarjeta profesional.
POST /api/documentos/subir (multipart/form-data).
En espera de verificación
Estado PENDIENTE. El médico puede usar la plataforma pero sus documentos están en revisión por el administrador.
El admin puede cambiar el estado a: EN_REVISION → VERIFICADO / RECHAZADO / SUSPENDIDO.
Panel médico activo
Ve sus pacientes asignados, sus consultas recientes y recibe alertas por email ante casos graves.
GET /api/medico/mis-pacientes · GET /api/medico/consultas-pacientes
AlertaService envía email automático ante consultas GRAVE o MODERADO de sus pacientes.
Panel de control
Vista con estadísticas globales: total médicos, verificados, pendientes, en revisión y total pacientes.
GET /api/admin/estadisticas → Contadores en tiempo real desde la base de datos.
Verificación de médicos
Lista filtrable de médicos. Al hacer clic abre un modal con perfil + documentos. Puede ver cada documento y cambiar su estado.
El botón "Ver" usa axios { responseType: 'blob' } para servir el archivo con JWT. Luego abre con URL.createObjectURL().
PUT /api/admin/documentos/{id}/estado
Gestión de usuarios
Tabla paginada (20/página) con filtros por nombre, rol, ciudad y estado. La página actual se persiste en la URL.
GET /api/admin/usuarios?pagina=0&nombre=&rol=&ciudad=&estado=
Usa JPA Specification con subquery para filtrar por ciudad/estado del perfil médico.
La URL se actualiza con router.replace() para preservar posición al volver.
Asignación médico-paciente
Mapa Leaflet con todos los pacientes (azul=con GPS, naranja=sin GPS) y médicos (verde). Selecciona un paciente y ve los médicos más cercanos ordenados por distancia.
Fórmula Haversine para calcular distancia entre coordenadas GPS.
POST /api/admin/asignacion · DELETE /api/admin/asignacion/{pacienteId}
Paciente ingresa síntomas
Describe en texto libre lo que siente. No hay formularios estructurados, el LLM interpreta el lenguaje natural.
Ejemplo: "Llevo 2 días con fiebre de 39°C, dolor de cabeza intenso y náuseas"
OllamaService analiza
Se envía el texto al modelo llama3.2:3b con un prompt estructurado que fuerza respuesta JSON.
Prompt: "Responde EXACTAMENTE en formato JSON: {nivel: LEVE|MODERADO|GRAVE, recomendacion: texto}"
Endpoint: POST http://localhost:11434/api/generate
Fallback si Ollama no está disponible
Si el LLM falla, el sistema activa el analizador por palabras clave que clasifica con la misma lógica.
GRAVE dolor de pecho, dificultad respiratoria, pérdida de consciencia
MODERADO fiebre, vómitos, mareos, dolor abdominal
LEVE todo lo demás
Alerta automática al médico
Si el nivel es GRAVE o MODERADO y el paciente tiene médico asignado, se dispara un email automático.
AlertaService usa JavaMailSender con Gmail SMTP (puerto 587, STARTTLS).
El email incluye: nombre del paciente, nivel de gravedad, síntomas y recomendación del sistema.

🛡️ Guarda de perfil incompleto

Si mc_perfil_ok !== "true" en localStorage, el router redirige automáticamente al formulario de perfil correspondiente al rol. Solo se permiten las rutas /perfil-paciente, /registro-medico y /mi-perfil. Esta guarda opera en router.beforeEach() de Vue Router.

Inicio rápido

Cómo ejecutar el proyecto

4 pasos para tener MediCheck IA corriendo en local.

1
Base de datos PostgreSQL
Crear la base de datos. Hibernate crea las tablas automáticamente al iniciar el backend.
-- En psql o pgAdmin
CREATE DATABASE medicheck_db;
2
Ollama (opcional)
Descarga el modelo de IA. Si no está disponible, el sistema usa el analizador de fallback automáticamente.
ollama pull llama3.2:3b
ollama serve  # puerto 11434
3
Iniciar el backend
Spring Boot en puerto 8080. El DataSeeder crea los usuarios de prueba automáticamente.
cd medicheck/backend
.\mvnw spring-boot:run  # Windows
./mvnw spring-boot:run  # Linux/Mac
4
Iniciar el frontend
Vue 3 + Vite en puerto 5173. Instala dependencias la primera vez.
cd medicheck/frontend
npm install
npm run dev  # http://localhost:5173
